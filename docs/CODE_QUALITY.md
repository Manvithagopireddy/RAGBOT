## 3. Test Suite Architecture

The test suite is organized into logical functional domains in `tests/`:

1. **Authentication & Token Security (`test_auth_security.py`)**:
   - Tests JWT cryptographic signature validation, expired token rejection, tampered token payloads, algorithm-substitution attacks (`alg: "none"`), and sliding-window rate limiting.
2. **Multi-Tenant Retrieval & Session Isolation (`test_data_isolation.py`)**:
   - Tests cross-user session access prevention, unauthorized document deletion blocking, and FAISS vector filtering by authenticated `user_id`.
3. **Document Lifecycle End-to-End (`test_document_lifecycle.py`)**:
   - Tests the complete lifecycle: upload $\rightarrow$ chunk $\rightarrow$ index $\rightarrow$ search $\rightarrow$ verify citation $\rightarrow$ delete document $\rightarrow$ verify immediate vector removal from FAISS and BM25 index.
4. **Adversarial Prompt Injection (`test_prompt_injection.py`)**:
   - 17 test cases executing direct prompt injections, indirect payload injections embedded in uploaded text, and context boundary escapes.
5. **API & Endpoints Integration (`test_api_chat.py`, `test_api_sessions_and_docs.py`, `test_api_health_and_auth.py`)**:
   - FastAPI endpoint validation using `TestClient`, checking status codes, headers, and payload validation.
6. **Retrievers & Search Algorithms (`test_hybrid_retriever.py`, `test_bm25_retriever.py`, `test_retriever.py`)**:
   - Mathematical verification of BM25 tokenization, reciprocal rank fusion (RRF), cross-encoder scoring, and citation generation.
